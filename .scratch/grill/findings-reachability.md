# 约束、限制与测试条款可达性审计（grill）

> 生成日期：2026-11-19。范围：PFA_PSG 脉冲信号发生板固件全部验收条款（F-/I-/T-/E-/N-）、一致性条款（C-*）与约束/限制表述。
> 任务背景：已确认「重开上传模式不补发结果事件」在真实主机行为下不可达，据此系统排查全部条款的不可达、多余与需澄清项。
> 结论标注：**可达**（前置条件在协议下可发生）、**不可达**（前置条件在协议下不可能出现）、**多余**（与其他条款重复或已被更一般条款覆盖，含恒真守卫）、**需澄清**（依赖文档未定义的行为或文档间冲突）。

## 0 方法与结论标准

1. 逐份读完必读文件：SRS（202 行）、board-pulse-gen（602 行）、ecsp-general（1253 行）、product-cardiac-pfa（38 行）、pulse-engine、current-settlement、uart-reception；辅助核对 params.md、GLOSSARY.md、ambiguities.md、firmware-architecture.md。
2. 建立可达状态空间（§1）：业务状态 × 会话/握手状态 × 上传模式 × 命令状态矩阵，推导可达组合与不可达组合；主机命令顺序取自产品/板卡/ECSP 规范中明文规定的序列（上电探测 → 版本核对 → 重新配置 → 启动；重复握手 → 版本核对 → 重新配置 → 新启动），主机行为中未文档化的部分（如「版本核对后首个命令是 0x0F」）单独列为外部依赖。
3. 对每条条款检查其前提（状态组合、事件序列、配置）能否由协议行为序列产生；测试条款额外检查互斥前提（同一时刻要求两种互斥状态）与重复验收（同一行为被多条条款重复覆盖）。
4. 不可达的常见成因：前置条件依赖不支持的命令（0x08–0x0E 在 PSG 回 0x04）、依赖主机不做某事的假设、数值上恒真的分支、门控把触发条件永远挡掉。

## 1 可达状态空间摘要

### 1.1 业务状态（脉冲引擎，GLOSSARY·脉冲引擎）

- **空闲**：无运行且非电流异常。杆状态按 F-028（未使能=杆选通，使能=AB 杆对；bit1 置位时冻结）。
- **运行**（子态：等待 R 波 · 触发延迟 · 出波 · 结算 · 触发间歇）：由受理启动进入。
- **电流异常态**：仅由运行进入（过流检出 / 过流锁存 / 欠流；串级超时**不**进入，只终止运行并记日志，F-041）。

转移：
- 空闲 → 运行：协议启动（0x30 控制码 0x01）或端口启动（正向过渡），门槛见 F-004/E-002（两路电压、两路阈值、序列参数已配置；边沿触发使能时另需 0x36；bit1 未置位、无过流检出、锁存无效）。门槛未满足：协议 0x13、端口忽略该次过渡。
- 运行 → 空闲：运行完成（F-011）、中途停止（F-012）。
- 运行 → 电流异常态：E-001（过流）、F-042（欠流）。
- 电流异常态 → 空闲：0x3D 清除（I-021/E-004），同时做过流锁存复位。
- **空闲时发生过流不进入任何状态**：比较器检出只在启动门槛处生效（E-002）；锁存按 E-003 置故障字 bit1（不改业务状态）。

### 1.2 会话/握手状态（从机侧）

- **等待连接**：仅上电/复位后存在。只处理 0x01；受支持的非握手请求回 0x10，未知命令回 0x04（§4.2.2）。
- **已连接/就绪**：握手应答 0x00 后进入；停止周期握手上报。从机**不回退**到等待连接（板卡 §2：PSG 不独立检测掉线）；重复 0x01 触发 I-012 板内重置后仍保持就绪。
- 可达组合：等待连接 × 空闲（唯一；端口启动在上电默认未配置下门槛不满足，故等待连接 × 运行不可达）；就绪 × {空闲, 运行, 电流异常态}（全可达，含电流异常态期间重复握手，I-021 已覆盖）。

### 1.3 上传模式（0x0F）

- 上电默认关闭（C-0x0F-01）。门控对象：0x0A、0x0E、0x11、0x3C；0x01 握手上报与 0x10 心跳豁免。
- 板卡例外（C-0x11-02/I-030）：同一会话收到 ≥1 条发往本板的合法命令后，**新置位**故障立即上报 0x11，不占用事件队列。
- **与 I-012 的交互未定义**（见 U-01）。
- 主机行为前提（外部依赖，见 U-08）：版本核对后首个命令为 0x0F(0x01)，之后不关闭——此行为不在本仓库任何文档中（A-03 中控板规范待补）。

### 1.4 命令状态矩阵（表 3-2）受理规则

- 获取类（0x31/0x33/0x35/0x37/0x39/0x3B/0x3F/0x41/0x43）：三态全受理。
- 设置类（0x32/0x34/0x36/0x38/0x3A/0x3E/0x40）与 0x42：空闲受理；运行 0x11；电流异常态 0x15。
- 0x30：空闲按门槛 0x13/受理，运行 0x11，电流异常态 0x15；源不匹配时空闲 0x12、运行（停止）0x12、电流异常态 0x15（优先）。
- 0x3D：空闲受理（按 bit1 分支）、运行 0x11、电流异常态受理并回空闲。
- 端口过渡：空闲正向=启动请求（门槛未满足忽略）、运行正向=忽略、运行负向=停止、其余忽略。
- **矩阵未覆盖的通用命令**（0x02/0x03/0x04/0x05/0x06/0x07/0x0F/0x12）在三态下的受理规则缺失（见 U-02）。

### 1.5 可达性总图（关键结论）

| 组合 | 可达性 |
| --- | --- |
| 等待连接 × 空闲 | 可达（上电默认） |
| 等待连接 × 运行 / 电流异常态 | 不可达（无配置、无会话） |
| 就绪 × 空闲 / 运行 / 电流异常态 | 全可达 |
| 上传模式 开/关 × 空闲 | 可达（0x0F 任一值） |
| 上传模式 关 × 运行/电流异常态 | 依赖 U-02（0x0F 运行中受理与否未定义） |
| 握手后、0x0F 开启前，空闲锁存置位 → 0x11 | 可达（I-030 例外窗口） |
| 上电前监测读取置位 bit1 → 0x11 | **不可达**（门控挡住，见 R-02/U-04） |
| 上传模式 关闭→重开 且期间有被抑制事件 | **不可达**（主机不关闭，见 R-01/U-08） |
| 0x08–0x0E 相关任何机制路径 | **不可达**（本板回 0x04） |

## 4 重点发现明细

### 4.1 不可达（22 条）

#### R-01 X-17 GLOSSARY·结果事件「不补发」句（本审计起始用例）

「上传模式关闭期间这一帧不发送；再次开启，或握手把模式设回开启，都不补发。」(GLOSSARY.md:430)

- 前提链条：主机版本核对后首个命令是 0x0F(0x01)，之后从不关闭上传模式（外部主机行为，见 U-08）；结果事件（0x3C/0x11）只在启动后的运行中产生，必然晚于 0x0F 开启。
- 因此「关闭期间有事件被抑制 → 再次开启/握手重开」的前提在真实主机行为下不可能出现，「不补发」规则无法被验收、也无从违反。
- 该句还存在第二个问题：无规范正文支撑（前次一致性审查 T-17 已报：C-0x0F-01、§4.6 均无「不补发」条款）。
- 处置建议：删除该句或改为「上传模式关闭期间被抑制的事件不补发（0x3C 同规则）」，并明确 I-012 对上传模式的处置（U-01）后再决定是否保留「握手重开」分支。

#### R-02 C-0x11-03 括注「包含开始监测前读到锁存已有效的情形」

- E-003 规定上电、开始监测锁存变化前读取锁存电平，有效即置 bit1；C-0x11-03 承诺该情形触发 0x11 上报。
- 但 C-0x0F-01（上电上传默认关）+ C-0x11-02（仅「会话内已收到 ≥1 条合法命令后新置位」才立即上报）把上电即置位的 bit1 永远挡住：置位发生在任何命令之前（上传关、无命令），其后到达的命令只满足「新置位」例外而该位已非新置位。
- 结论：上电前监测读取置位 bit1 的 0x11 上报不可达；主机只能经 0x12 发现。与 C-0x11-03 括注直接矛盾（U-04）。

#### R-03 组：0x08–0x0E 命令族与长耗时/低功耗机制（20 条，对 PSG 恒空洞）

PSG 声明：0x08/0x09 → 0x04、不发 0x0A（I-023）；0x0B–0x0E → 0x04、不发 0x0E（I-031）。因此下列条款的前置条件在 PSG 上永不成立：

- C-0x07-02（长耗时事务在途时的抢占复位）
- C-0x08-01、C-0x08-03、C-0x09-01、C-0x09-02、C-0x0A-01、C-0x0A-02、C-0x0A-03（自检族）
- C-0x0B-01（低功耗链路行为）
- C-0x0C-01、C-0x0C-03、C-0x0C-05、C-0x0D-01、C-0x0D-02、C-0x0E-01、C-0x0E-02（升级族）
- C-0x10-03 的「长耗时命令执行期间」「低功耗暂停」分量
- X-08（§4.4 机制）、X-09（§4.5 抢占式复位条目）、X-10（§4.6 机制）

这些是通用层条款，对支持对应命令的其它板卡仍有效；审计结论是**对 PSG 不可达、不进入 PSG 验收范围**。建议在符合性矩阵或 SRS 中明示「0x08–0x0E 相关通用条款对 PSG 不适用」，避免验收计划为空洞条款分配用例。
