### 0.2 编号与列约定

| 记号 / 列 | 规则 |
| --- | --- |
| `F-` / `I-` / `T-` / `E-` / `N-` | 前缀含义：F 功能、I 接口、T 时序、E 异常与安全、N 非功能；三位数字，各族自 001 起 |
| 编号连续性 | 段内连续、不跳号、不重排、不新增、不删除；跨族不互相替换 |
| `[作废，占号保留]` | 条款已作废但仍占用原号，不得复用该号（见 I-022、I-026、E-011、N-007） |
| `[本版不实现]` | 需求成立但本版不交付，保留条款与编号（见 I-023、T-012、N-005、E-010） |
| 需求表固定列 | `ID` ｜ `需求（可判定语句）` ｜ `验证方式` ｜ `参数引用` ｜ `追溯`，五列顺序不变 |
| `参数引用` 列 | 只写 `PRM-xxx`（可多个，用「、」分隔）；params.md 无对应项写 `—`，并在 §0.4 登记 |
| `追溯` 列 | 命令码（`0xNN`）、接口需求 ID、引脚（`§7`）或 `见 OPEN_QUESTIONS.md Q-xxx`；原文「依据」信息并入本列保留 |
| `[待确认 Q-xxx]` | 该处受未裁决问题影响，暂按建议值实现，裁决后回填（语义见 README §3） |
| 「应 / 不得 / 当…时」 | 强制条款；「可 / 建议」非强制。原文「必须」统一降为「应」（README §3） |
