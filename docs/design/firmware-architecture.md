# PSG v3 固件架构

分层、依赖方向、源文件目录及外设接口经 2026-11-19 的 Q18 确认。设计依据见[嵌入式固件分层调研](embedded-layering-research.md)。

按职责从上到下分为应用、运行控制、基础服务、板级执行和 MCU 驱动五层。运行控制层持有业务状态。协议请求和端口启停事件使用同一套裁定，由当前启停输入源决定权限。计划生成、样本结算和外设执行分别使用各自的接口。应用可直接调用 ECSP 和标识服务，运行控制可直接调用板级执行接口。调度采用 FreeRTOS 全量任务化（[ADR 0001](../adr/0001-bare-metal-cooperative-scheduling.md)）：调度、脉冲引擎、电流结算、UART 收发和标识服务各自成任务，任务监视器负责喂狗。

## 1. 任务、优先级与交接

- **任务清单。** 任务监视器（最高优先级，喂狗裁定与复位原因记录）、脉冲引擎与电流结算（高优先级，出波推进与串级结算）、调度与 ECSP 分派、UART 收发（中优先级）、标识服务（最低优先级，Flash 分步擦写）。任务级周期、最坏执行时间（WCET）与优先级预算取代协作式每轮预算：结算任务对应 PRM-117～PRM-119，ECSP 对应 PRM-101～PRM-106。
- **ISR→任务交接契约。** 每类事件单独定义去向、容量和超限处置：串结束（HRTIM TIMA）→脉冲引擎任务队列，容量 2，队列满视为失约并按 F-041 终止运行；DMA 半传输/传输完成就绪→结算任务队列，容量 2，同一半区重复事件合并并计数；过流检出、过流锁存、端口停止等保护事件→脉冲引擎任务队列，容量 4，不可丢弃、溢出时合并为多源事件并计数（停波本身由 ISR 快速路径直接完成）；UART IDLE/DMA 接收进度→UART 任务队列，容量按 T-011 最坏负载核定，溢出丢弃最旧字节并计接收溢出、触发重新同步（HW-03）。
- **NVIC 优先级（PRM-727～PRM-730）。** 保护类 EXTI4/EXTI9_5/HRTIM1_FLT/HRTIM1_TIMA 优先级 4（最高），DMA1/USART1/USART2 优先级 5，SysTick 优先级 15（FreeRTOS 时基，最低）；PendSV/SVC 按 FreeRTOS 惯例取最低优先级。FreeRTOS 管理的 ISR 只使用 FromISR 接口入队或发通知，不在中断内做业务处理。
- **最坏延迟预算。** 过流检出与过流锁存的停波沿硬件通路在 ISR 内直接完成，最坏延迟按 PRM-509、PRM-510（T-005 验收）；采样就绪到结算任务的队列调度延迟计入串级截止验证（F-041）；中断抢占延迟计入 T-007、T-008 验收。

## 2. 应用层 `app/`

- 静态装配设备和模块实例，创建 FreeRTOS 任务并启动调度器。调度任务推进 ECSP 分派和非易失写入编排，脉冲引擎与结算任务按期处理到期工作。
- 保存 PSG 板卡命令支持声明和载荷映射。ECSP 任务按通用规则检查后，调度任务解码交给业务模块，将业务结果映射为应答或主动上报。用 ECSP 的线路发送完成信息编排 0x07 复位。合法重复握手通过调度任务编排，由脉冲引擎任务执行板内恢复，由 ECSP 服务管理会话和去重缓存。
- 产出的应答和主动上报均提交给 ECSP 发送队列。0x11 上传门控与板卡会话例外按会话例外优先裁定：同一会话收到至少一条发往本板的合法命令后新置位的故障立即上报，不受上传模式关闭影响（I-028）；其余 0x11 受上传模式门控。

## 3. 运行控制层 `control/`

- 唯一持有已提交的运行配置、运行阶段、启停权限、故障字 bit0 和状态快照。按状态矩阵裁定请求，设置命令以整笔校验和提交为边界。已提交的运行配置仅存于 RAM，复位恢复上电默认（E-009）；非易失保存仅软件版本、硬件版本、序列号和标定表。脉冲引擎在这里对应运行控制模块。
- 协调直接触发、R波触发、各群和各串的推进，确定杆对、杆选通和导通等待，依据结算结果与截止时间决定是否发出下一串许可。串级超时走 F-041 的终止路径。杆选通请求由控制层持有待完成操作，板级提供实际切换时刻，导通等待到期后才产生成功应答。
- 根据采集和保护事实决定普通读数、诊断电流和计数的发布时机。按事件发生时的运行归属区分运行中的过流与空闲过流锁存。0x3D 清除（复位脉冲 → 5 ms 锁存清除确认等待 → 重读）与锁存复位、杆状态恢复保持在同一次业务裁定内；重读仍有效时置 bit0 并应答 0x20（E-003、I-021）。
- 0x3C 结果快照与运行态解耦：最近两次运行结果存于 RAM 双槽、轮换写入，主机可随时经 0x3C 或 0x31 查询，启动不依赖先取走结果；复位后快照丢失。

## 4. 基础服务层 `services/`

- `ecsp/` 提供帧编解码、地址过滤、半包计时、会话和事务机制、上传门控及发送队列。输入是带原接收时刻的字节和应用提交的应答、上报。
- `identity/` 管理软件版本、硬件版本、序列号及其记录格式，分步推进擦写、校验、提交与默认值修复。记录采用 A/B 双槽、槽序号与 CRC，掉电或校验失败回退旧槽，上电记录体检失败以默认值修复（[ADR 0002](../adr/0002-dual-bank-flash-layout.md)）；擦写窗口内禁止读取 bank2，读路径在擦写期间走 RAM 缓存或拒绝。擦写与校验成功后提交新值。
- `waveform/` 用候选配置和随固件发布的标定表生成可预计算的出波计划。按 F-024、F-025、T-009 计算驱动时长，并用板级提供的实际计数周期执行量化。板级执行用计划中的数值配置具体外设。生成计划与整笔配置提交一起在脉冲引擎任务内完成。
- `current/` 根据通道、串标识、样本数及已捕捉的样本范围完成齐样检查、电流换算、串群及本轮累计、阈值判定。对外提供按通道的结算结果和证据。物理 DMA 所有权在板级，下一串许可和状态快照在运行控制。

## 5. 板级执行层 `bsp/`

- 通过 `sequence_io.h` 表达序列执行所需的操作、带标识的许可、已捕获事件和有效样本视图。脉冲引擎任务在提交启停输入源时同步板级端口停止授权。PSG v3 实现在一个板级模块内协调 HRTIM、ADC、DMA 和杆驱动。板级配置集中持有实际引脚、外设实例、NVIC 优先级和 Flash 区域。
- 执行预装载的波形，按原定硬件时刻启动已放行的串，执行杆驱动并捕捉端口及 R 波事件。DAC、比较器和独立过流锁存的硬件保护，以及端口停止的快速路径均在这里完成。
- 私有持有 DMA 缓冲区。事件提供运行、群和串标识，以及可读半区或终止时捕捉的有效样本边界。接口约定样本视图的有效期和归还方式。硬件路径执行即时封锁，中断捕捉故障来源及边界，脉冲引擎任务读取后裁定业务状态。完成或取消后作废该串的未消费许可。
- ADC 采样阶段约 257 ns（PRM-708、PRM-710）长于最短目标脉宽 200 ns（PRM-307、PRM-308），采样窗口有效性与台架验证回退方案见[串级结算设计](current-settlement.md#截止时间与验证)。

## 6. 看门狗与复位

- **任务监视器（E-008）。** 仅任务监视器有权喂狗。它按监视周期采样各任务的推进标记：

  | 关键模块（任务） | 最大推进间隔的核定依据 |
  | --- | --- |
  | 脉冲引擎 | 脉冲串间隔（PRM-305）与脉冲群间隔（PRM-306）内的推进 |
  | 电流结算 | 结算任务周期/WCET/截止时间（PRM-117～PRM-119） |
  | 调度与 ECSP | 应答时限（PRM-101～PRM-106）与心跳间隔（PRM-111） |
  | UART 接收 | 半包窗口（PRM-115） |
  | 标识服务 | 分步推进，单步不超过页擦除时间（PRM-739） |

  任一任务自上次推进起超过其最大推进间隔即计逾期，连续逾期达到拒喂阈值（板级配置；正常喂狗的最坏间隔须小于 PRM-603 的最短硬件窗口）即拒喂，IWDG 复位。
- **复位原因。** 复位原因寄存器记录 IWDG、掉电、引脚与软件复位来源，上电启动时读取，供 E-008 验收与故障排查。0x07 采用系统复位，复位后故障字按 E-003 上电自检重判、运行配置回上电默认；IWDG 运行于独立时钟域、跨系统复位不清零，启动阶段须尽早接管喂狗。
- **上电安全态。** 初始化完成前输出封锁、六杆不导通（E-006）；初始化完成后按上电默认杆选通（PRM-325 六杆全通）进入空闲。

## 7. MCU 驱动层 `drivers/`

- **UART 和 Flash。** `uart.h` 提供带接收时刻的字节、非阻塞发送和线路发送完成。`flash.h` 提供读取、启动擦写及查询结果。ECSP 和标识服务分别使用这两个接口。
- **ADC + DMA。** `adc_capture.h` 提供外部触发采集、启动与停止、DMA 半传输和传输完成、写入进度与错误。BSP 配置通道、触发源和循环缓冲区，并将就绪样本关联到运行、群和串。电流服务从板级样本视图读取有效样本。
- **普通时基和看门狗。** `timebase.h` 定义单调时间戳的读取、单位和回绕约定，用于普通截止时间（PRM-115 半包计时、串级截止）。FreeRTOS 时基由 SysTick 提供，任务延时使用 RTOS 接口。`watchdog.h` 提供刷新操作，由 BSP 配置并启动硬件看门狗，由任务监视器按 E-008 决定何时刷新。
- **精确定时输出和板级保护。** `sequence_io.h` 向运行控制提供装载、放行、封锁和读取事件等操作。BSP 用 STM32 HRTIM 驱动实现定时与输出控制，并用 HAL/LL 配置 GPIO、EXTI、DAC 和比较器。杆状态、端口事件和过流锁存是板级接口上的能力。过流锁存保护沿硬件通路执行，端口快速停波由板级中断直接执行。
- 按调用场景选择静态绑定方式。发布版与调试版共享已有 UART 类型化设备模型。固定实例可直接调用构建时选定的实现，主机测试可链接同一公开接口的替代实现。驱动拥有寄存器操作、搬运进度、完成和错误状态，板级配置拥有具体的资源绑定。

## 源码依赖与状态归属

- `app/` 使用 `control/`、ECSP 和标识服务的公开入口。启动入口绑定目标板实例。`control/` 使用波形计划、电流结算和 `sequence_io.h`。计划参数与装载描述通过值数据交接，板级依赖自己的执行接口。
- ECSP 和标识服务分别依赖 `uart.h`、`flash.h`。任务监视器的喂狗使用 `timebase.h`、`watchdog.h`。`bsp/psg_v3/` 通过 `adc_capture.h` 获取采集进度，并通过 STM32G4 驱动绑定具体外设。板级和驱动用各自的事件与完成接口经队列向任务交付观测结果。
- 模块私有头文件只在各自目录内使用。主机测试可替换设备实现，沿实际公开入口驱动命令和运行状态。

## 用实际场景校核

1. **0x34 写入、0x35 读回。** 调度任务映射线上字段，运行控制校验候选配置，计划服务生成对应的执行参数。候选配置和计划同时提交。读回由运行控制提供原值，后续启动装载与已提交配置对应的计划。
2. **上一串结算与下一串放行。** BSP 捕捉串结束、各参与通道的 DMA 就绪及样本有效范围，经队列交结算任务。运行控制核对事件标识，调用电流服务结算并决定放行。BSP 只执行与该串标识和原定开始时刻匹配的许可，到时缺许可则保持输出封锁。脉冲引擎任务按 F-041 终止本次运行。分别测量取样、结算和放行用时。
3. **端口停止与过流并发。** 快速路径先封锁输出并保留已发生的过流来源和样本边界。脉冲引擎任务根据事件的运行归属更新异常记录和状态快照，必要时由调度任务提交 0x3C。空闲时过流锁存由无效变有效，运行控制不置故障字，按 I-028 会话例外提交 0x11；故障字 bit0 仅由上电自检或 0x3D 清除后重读仍有效置位（E-003、I-021）。
4. **版本写入期间保持通信与出波时序。** 标识服务任务分步推进 Flash，脉冲引擎与结算任务按期处理出波与结算，ECSP 继续按预算推进；擦写窗口内记录读取走 RAM 缓存。烧写时序和实际串级余量通过实板验证。

主机自动化测试通过公开接口注入板级事件和带接收时刻的串口数据。PC 串口联调在两种构建上运行同一套 ECSP 用例。实板台架验收串级截止时间、保护停波延迟、DMA 归属与 Flash 擦写负载等物理行为。三类入口的详细覆盖范围见固件实现规格。
