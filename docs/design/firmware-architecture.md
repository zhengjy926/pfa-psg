# PSG v3 软件架构设计说明书（SAD）

状态为评审稿。子系统组成、边界与分配见 [PSG-SyAS](psg-subsystem-architecture.md)，系统要求见 [PSG-SyRS](../syrs/psg-subsystem-requirements.md)，软件行为和验收限值见 [SRS](../srs/pulse-gen-firmware.md)。本文描述目标架构。实现状态按 [实现缺口](../implementation-gaps.md) 核对。

分层、依赖方向、源文件目录及外设接口经 2026-11-19 的 Q18 确认。设计依据见[嵌入式固件分层调研](embedded-layering-research.md)。

按职责从上到下分为应用、运行控制、基础服务、板级执行和 MCU 驱动五层。运行控制层持有业务状态。协议请求和端口启停事件使用同一套裁定，由当前启停输入源决定权限。计划生成、样本结算和外设执行分别使用各自的接口。调度采用 FreeRTOS 全量任务化（[ADR 0001](../adr/0001-bare-metal-cooperative-scheduling.md)）六任务清单：任务监视器（最高优先级）、脉冲引擎、电流结算、协议任务（ECSP 解帧去重、调度编排与裁定链单一所有者）、UART 接收、标识服务（最低优先级）；板级执行层与 MCU 驱动层不持有任务，仅提供接口。0x30 请求路径经 UART 接收任务 → 协议任务 → 脉冲引擎任务共 2–3 跳。

## 1. 任务、优先级与交接

解帧在协议任务上下文执行。按最坏执行时间限制单次调度的解帧工作量，覆盖坏帧和重同步。验证时叠加通信积压，核对 N-003、T-008 和 T-011。FreeRTOS 选型、任务划分及交接机制以 [ADR 0001](../adr/0001-bare-metal-cooperative-scheduling.md) 为设计依据。

- **任务清单。** 任务监视器（最高优先级，喂狗裁定与复位原因记录）、脉冲引擎（高优先级，启停裁定执行、出波推进、杆控制与计划生成）、电流结算（高优先级，串级结算）、协议任务（中优先级，ECSP 解帧去重、调度编排与裁定链单一所有者）、UART 接收（中优先级）、标识服务（最低优先级，Flash 分步擦写）。任务级周期、最坏执行时间（WCET）与优先级预算取代协作式每轮预算：群级结算默认唤醒周期 10 ms，任务 WCET ≤40 ms，等待与结算合计 <50 ms 且小于最小群间隔；协议应答时限为获取、设置、动作类默认各 50 ms，0x03/0x05 首次应答各 3000 ms，0x07 应答 50 ms。任务×层职责矩阵：

  | 任务 | 层职责 | 事件入口 | 事件出口 | 持有状态 |
  | --- | --- | --- | --- | --- |
  | 任务监视器 | svc/watchdog_monitor：任务监视与喂狗 | 监视周期到期（timebase 时基） | IWDG 刷新（watchdog） | 各任务推进标记、逾期计数、复位原因 |
  | 脉冲引擎 | run/pulse_engine：启停裁定执行、出波推进、杆控制、计划生成 | 已裁定操作（协议任务）、保护事件（psg_event.h）、串放行任务通知（结算任务） | 装载/放行/封锁命令、状态快照、0x3C/0x11 数据 | 已提交运行配置、运行阶段、启停权限、故障字 bit0、状态快照、未消费许可 |
  | 电流结算 | run/settlement：齐样、换算、阈值判定 | 串结束事件、DMA 就绪事件（结算任务队列） | 任务通知（放行或 F-041 终止结论）、结算结果 | 通道样本视图、串群累计 |
  | 协议任务 | app/psg_ecsp：ECSP 解帧去重、会话编排、裁定链单一所有者 | UART 接收事件、应用提交的应答/上报 | 已裁定操作、应答/上报、去重回放 | 会话状态、上传门控、去重窗口（经 svc/dedup） |
  | UART 接收 | bsp UART 接口：环形缓冲消费、字节交接 | USART IDLE/DMA 接收进度 | 字节事件（带接收时刻） | 接收环形缓冲、重同步状态 |
  | 标识服务 | svc/identity：记录擦写、校验、修复 | 版本/序列号写入操作 | 应答 | 擦写进度、RAM 缓存 |

- **裁定链单一所有者。** 一条请求的裁定沿单一定序流水线完成，协议任务是唯一编排者，串行化 ECSP 公共检查 → 状态矩阵 → 执行；ECSP 只提供去重查询、回放寄存、序号管理原语（svc/dedup），状态矩阵结论由脉冲引擎提供，脉冲引擎只执行已裁定操作。去重回放存拒绝码与短载荷，I-007 回放一致性可证。
- **ISR→任务交接契约。** 每类事件单独定义去向、容量和超限处置：串结束（HRTIM TIMA REP 中断，串边界定界见 §5）→结算任务队列，容量 2，队列满视为失约并按 F-041 终止运行；DMA 半传输/传输完成就绪→结算任务队列，容量 2，同一半区重复事件合并并计数；过流检出、过流锁存、端口启停等保护事件→脉冲引擎任务队列，容量 4，不可丢弃、溢出时合并为多源事件并计数（硬件执行停波，端口事件经 TIMA CPT1 捕获由 ISR 入队，见 §5）；UART IDLE/DMA 接收进度→UART 接收任务队列，容量按 T-011 最坏负载核定，溢出丢弃最旧字节并计接收溢出、触发重新同步（HW-03）。结算任务以 `xQueueReceive(portMAX_DELAY)` 事件驱动收齐同串事件，判定完成经任务通知唤醒脉冲引擎任务执行放行或 F-041 终止。串级结算为事件驱动、无周期延迟；默认 10 ms 唤醒周期仅约束群级结算等待。
- **事件契约（psg_event.h）。** 板级产出的事件统一为结构体，携带类型、运行序号、群号、串号、单调时间戳与有效样本边界。归属裁定以事件携带的硬件事实为准，不依赖任务侧运行状态快照。每类队列的溢出/合并计数纳入 0x31 状态块或 RTT ERROR 级调试日志（N-005），供 F-041 失约阶段定位。
- **NVIC 优先级。** 保护类 HRTIM1_TIMA/EXTI9_5/HRTIM1_FLT 优先级 4（最高），DMA1/USART1/USART2 优先级 5，SysTick 优先级 15（FreeRTOS 时基，最低）；PendSV/SVC 按 FreeRTOS 惯例取最低优先级。`configMAX_SYSCALL_INTERRUPT_PRIORITY = 4`（0–3 预留不用），登记入 psg_board_config.h 与 FreeRTOSConfig；FreeRTOS 管理的 ISR 只使用 FromISR 接口入队或发通知，不在中断内做业务处理。每个保护类 ISR 的 WCET 预算 <2 µs @170 MHz（约 340 周期）逐项登记：HRTIM1_TIMA = 读 REP/CPT 标志 + 串边界与端口事件证据捕捉（CPT1 读值 + PB4 电平判向）+ 入队 + 清标志；EXTI9_5 = 三源位测试 + 证据捕捉 + 入队 + 清标志。
- **最坏延迟预算。** 比较器检出和独立过流锁存须分别通过硬件在 1 µs、10 µs 内停止双路实际功率输出（T-005）。独立锁存关断连线待 PSG-23 确认。端口停止的 MCU 快路径采用 EEV7 输出复位，对应预算为 66 ns（DS12288 Table 62，按适用条件验收 T-005-A），端到端功率关断按 T-005-B 验收；端口事件捕捉延迟计入状态更新、不影响停波；采样就绪到结算任务的队列调度延迟计入串级截止验证（F-041）；中断抢占延迟计入 T-007、T-008 验收。
- **静态 RAM 预算（N-002）。** 全部静态分配（N-001 禁动态内存/递归/VLA），逐项预算如下，总目标 ≤32 KB，为 64 KB 上限的一半；map 文件核对写入 N-002 验收。

  | 条目 | 预算 | 说明 |
  | --- | --- | --- |
  | FreeRTOS 内核 | 3–4 KB | 内核对象与调度开销 |
  | 任务控制块 | 6×TCB | 六任务 TCB，栈金丝雀另计 |
  | 任务栈 | 6×（512 B–1 KB） | `configCHECK_FOR_STACK_OVERFLOW=2` 栈顶金丝雀；栈水位上电与调试上报 |
  | 队列 | 按容量×元素 | 容量推导式 = 最坏产生率 × 最坏消费延迟，与 T-011、F-041 联立 |
  | DMA 采样缓冲 | 2 KiB | 每路 2×256×2 B = 1 KiB（DMA 数据宽度 16 位），两路合计 |
  | UART 接收环形 | 2×1 KiB | 循环 DMA 零拷贝环形 |
  | 运行快照 | 2×≤30 B | 双槽快照 |
  | 去重 FIFO | ≤128 B | 8 笔 |
  | ECSP 收发缓冲 | ≤1 KiB | 收发各按 最大帧 450 B 核定 |
  | 合计目标 | ≤32 KB | 64 KB 上限的一半 |

## 2. 应用层 `app/`

- 静态装配设备和模块实例，创建 FreeRTOS 任务并启动调度器。协议任务推进 ECSP 解帧、去重、会话与裁定链编排；脉冲引擎与结算任务按期处理到期工作；标识服务任务编排非易失写入。
- 保存 PSG 板卡命令支持声明和载荷映射。协议任务按 ECSP 公共检查与状态矩阵完成裁定后解码交给业务模块，将业务结果映射为应答或主动上报。用 ECSP 的线路发送完成信息编排 0x07 复位。合法重复握手由协议任务编排，脉冲引擎任务执行板内恢复，ECSP 服务管理会话，去重查询与回放寄存经 svc/dedup 原语完成。
- 应答和普通上报通过 ECSP 发送队列仲裁。对满足 I-028 的 0x11，会话例外优先于上传门控，按板卡协议保留待发条件，无须占用普通事件队列。上报时延预算计入状态发布、协议任务唤醒、正在发送的帧及后续仲裁。按 PSG-20 的批准时限与 T-011 共同核定仲裁预算。空闲锁存上报和 0x3D 补发分别按 E-002 与 I-021。
- 编译期可配项集中登记于 `app_config.h`：群级结算唤醒周期（默认 10 ms）、协议口（发布版默认 USART2，单板调试版 USART1）、N-005 日志等级、任务监视周期与拒喂阈值、各队列容量；每项标注默认值与推导依据。验收固定默认配置为唯一基准，宏改动触发回归清单。

## 3. 运行控制层 `run/`

- 唯一持有已提交的运行配置、运行阶段、启停权限、故障字 bit0 和状态快照。请求按状态矩阵裁定，裁定链由协议任务单一编排（§1），本层提供状态矩阵结论并只执行已裁定操作；设置命令以整笔校验和提交为边界。已提交的运行配置仅存于 RAM，复位恢复上电默认（E-009）；软件版本和标定表随镜像发布，硬件版本与序列号作为运行时可写记录独立保存。本层对外接口为 `pulse_engine.h`（启停裁定执行、出波推进、杆控制、计划生成）与 `settlement.h`（齐样、换算、阈值判定）。
- 协调直接触发、R波触发、各群和各串的推进，确定杆对、杆选通和导通等待，依据结算任务的判定结论（经任务通知送达）与截止时间决定是否发出下一串许可。串级超时走 F-041 的终止路径。杆选通请求由控制层持有待完成操作，板级提供实际切换时刻，导通等待到期后才产生成功应答。
- 根据采集和保护事实决定普通读数、诊断电流和计数的发布时机。按事件发生时的运行归属区分运行中的过流与空闲过流锁存。0x3D 清除（复位脉冲 → 5 ms 锁存清除确认等待 → 重读）与锁存复位、杆状态恢复保持在同一次业务裁定内；重读仍有效时置 bit0 并应答 0x20（E-003、I-021）。
- 0x3C 结果快照与运行态解耦：最近两次运行结果存于 RAM 双槽、环形轮换，第三次运行覆盖最旧槽；快照为结算完成的拷贝，不引用活数据；主机可随时经 0x3C 或 0x31 查询，0x3C 上报不清槽，启动不依赖先取走结果；复位后快照丢失。快照与 0x31 状态块复用 psg_reports 打包函数。

## 4. 基础服务层 `svc/`

- `identity/` 从镜像构建信息读取软件版本，忽略旧软件版本记录。负责硬件版本和序列号可写记录的分步擦写、校验、提交与默认值修复。可写记录采用 A/B 双槽、槽序号与 CRC，掉电或校验失败回退旧槽，上电记录体检失败以默认值修复（[ADR 0002](../adr/0002-dual-bank-flash-layout.md)）；擦写窗口内禁止读取 bank2，读路径在擦写期间走 RAM 缓存或拒绝。擦写与校验成功后提交新值。
- `dedup/`（dedup.h）提供事务去重查询、回放寄存与序号管理原语（1 字节序号按 0–255 回绕，FIFO 深度 8 笔，含初发最多发送 3 次），由协议任务编排调用；动作类命令的记录保存请求载荷和原应答的可重建信息，含拒绝码与短载荷。线路发送完成只释放发送队列项。去重记录按 ECSP §4.3 的窗口、冲突和替换规则处理（I-007）。
- `fault/`（fault.h）归集故障字位与故障来源证据，对外提供故障字读清与来源查询；故障字 bit0 的上电自检与 0x3D 重读语义按 E-003、I-021。
- `watchdog_monitor/`（watchdog_monitor.h）实现任务监视与喂狗策略（§6）。
- 板级与任务间的共用事件结构体定义于 `psg_event.h`（§1 事件契约）。

## 5. 板级执行层 `bsp/`

PB4 负向过渡至 MCU 输出停止的路径预算按 T-005-A 核对。功率级还包含栅极驱动、开关器件和负载响应，单独按 T-005-B 测量。EEV7 对当前输出的复位须与持续封锁一起验证。若后续置位仍可发生，须在板级保护设计补齐持续封锁机制后再通过 F-012-B 验收。 [PSG-03、PSG-22](../ambiguities.md#psg-行为与验收)

- 通过 `sequence_io.h` 表达序列执行所需的操作、带标识的许可、已捕获事件和有效样本视图，通过 `psg_protection.h` 表达停波单所有者矩阵与保护通路接口。脉冲引擎任务在提交启停输入源时同步板级端口停止授权。PSG v3 实现在一个板级模块内协调 HRTIM、ADC、DMA 和杆驱动。板级配置集中持有实际引脚、外设实例、NVIC 优先级、FreeRTOS 中断阈值和 Flash 区域。
- 执行预装载的波形，按原定硬件时刻启动已放行的串，执行杆驱动并捕捉端口及 R 波事件。BSP 配置 DAC（drv/dac.h）、比较器（drv/comp.h）及 HRTIM 比较器故障输入，提供独立过流锁存的状态采集与复位，以及端口停止的快速路径。
- 私有持有 DMA 缓冲区。事件（psg_event.h）提供类型、运行序号、群号、串号、单调时间戳，以及可读半区或终止时捕捉的有效样本边界。接口约定样本视图的有效期和归还方式。硬件通路执行即时封锁（见停波单所有者矩阵），中断只捕捉故障来源及边界、不写输出寄存器，脉冲引擎任务读取事件后更新业务状态。完成或取消后作废该串的未消费许可。
- **停波单所有者矩阵（psg_protection.h）。** 比较器过流方案采用 HRTIM 硬件故障态（故障输出电平 INACTIVE，FLT 计数为 2）。独立过流锁存应有独立于调度的硬件关断及保持路径，关断接点按 PSG-23 核对。ISR 只捕捉故障来源与样本边界。比较器故障复位模式为「锁存」，保持 HRTIM 停止输出（[MCU 映射](../hw/mcu-pinmap.md) §2.4.3 固定配置随改，T-005 台架重验）；端口停止的 MCU 快路径采用硬件联动。PB4 复用 AF13=HRTIM1_EEV7（引脚源、双边沿、滤波 0000），EEV7 经 EXTEVNT7 直接复位两路输出（HRTIM_RSTx1R/RSTx2R），停波延迟 typ 56 / max 66 ns（DS12288 Table 62），不依赖中断与 NVIC；端口事件（启动正向过渡/停止负向过渡）由 EEV7→TIMA CPT1 捕获经 HRTIM1_TIMA_IRQn 入队，ISR 按 PB4 电平判向，事件捕捉延迟不影响停波。启停输入源为协议（0x3E）时屏蔽 EEV7 输出复位与捕获（[MCU 映射](../hw/mcu-pinmap.md) §2.8）。与过流故障通路（FLT4/5←COMP1/3）正交、互不占用。
- **串边界硬件定界（REP=N-1，RM0440 已核查）。** 每串按每串波形数 N（1–256） 装载 HRTIM Timer A 重复计数 REP=N-1，TIMA REP 中断即硬件精确的串结束事件（每串 1 次中断、零软件计数抖动）；重复计数按波形数派生，[MCU 映射](../hw/mcu-pinmap.md) §2.4.1 的重复计数「更新使能」。核查结论（RM0440 §28.3.4、§28.5.18）：REPR 运行期间可写，但写入值在更新事件（=重复事件）时转移，且 RPTR 每 REP 事件按当时有效值重载——串间窗口写 REPR 实际作用于下下串，须按波形表提前一串预取写入（≥1 ms 窗口可行；转移与重载同拍次序手册未明确，最坏再滞后一串，需台架实测）。群边界参数重载不经突发模式：G474 突发控制器只做输出空闲/运行、不写 CMP/PER/REP 寄存器（§28.3.15），改为软件预装载或 burst DMA（BRSTDMA=10、UPDGAT=0010 保证整组一致，§28.3.23）；「Timer A 重复」触发（TAREP）在 REP=N-1 时每 N 周期一次、REP=0 时每周期一次，N×T_PWM 小于突发周期时丢触发、须 TABM=1。
- ADC 采样阶段约 257 ns（12.5 个 ADC 周期，ADC 时钟 48.57 MHz）长于最短目标脉宽 200 ns，采样窗口有效性与台架验证回退方案见[串级结算设计](current-settlement.md#截止时间与验证)。

## 6. 看门狗与复位

- **任务监视器（E-008）。** 仅任务监视器有权喂狗。它按 100 ms 监视周期采样各任务的原子推进标记（只读、零共享资源，空闲健康态也周期性推进）：

  | 关键模块（任务） | 最大推进间隔的核定依据 |
  | --- | --- |
  | 脉冲引擎 | 脉冲串间隔（1–100 ms）与脉冲群间隔内的推进 |
  | 电流结算 | 事件驱动的串级结算（最短串间隔为 1 ms）与群级结算预算（10 ms 默认周期、≤40 ms WCET、合计 <50 ms 且小于最小群间隔） |
  | 协议任务 | 应答时限（获取、设置、动作类默认各 50 ms，0x03/0x05 首次应答各 3000 ms，0x07 应答 50 ms）与心跳间隔 |
  | UART 接收 | 半包窗口 |
  | 标识服务 | 分步推进，单步不超过页擦除时间（24.47 ms < 监视周期 100 ms） |

  任一任务自上次推进起超过其最大推进间隔即计逾期，连续 2 次逾期（拒喂阈值）即拒喂，IWDG 复位。最坏拒喂延迟 ≤3×监视周期+判定余量；最坏喂狗间隔 = 监视周期 + 监视器自身被 ISR 抢占上界，推导 <0.941 s（看门狗最短硬件窗口，E-008）。标识服务单步页擦除 24.47 ms< 100 ms 监视周期，不误判逾期。事件组可作实现备选，须满足：喂狗超时 <0.941 s、低频任务注销/注册。监视周期与拒喂阈值登记入 `app_config.h`。
- **复位原因。** 复位原因寄存器记录 IWDG、掉电、引脚与软件复位来源，上电启动时读取，供 E-008 验收与故障排查。0x07 采用系统复位，复位后故障字按 E-003 上电自检重判、运行配置回上电默认；IWDG 运行于独立时钟域、跨系统复位不清零，启动阶段须尽早接管喂狗。
- **上电安全态。** 初始化完成前输出封锁、六杆不导通（E-006）；初始化完成后按上电默认杆选通（0x3F，六杆全通）进入空闲。

## 7. MCU 驱动层 `drv/`

- **UART 和 Flash。** `uart.h` 提供带接收时刻的字节、非阻塞发送和线路发送完成。`flash.h` 提供读取、启动擦写及查询结果。psg_ecsp 和标识服务分别使用 `uart.h`、`flash.h`。
- **ADC 采集、DAC 与比较器。** `adc_capture.h` 提供外部触发采集、启动与停止、DMA 半传输和传输完成、写入进度与错误。BSP 配置通道、触发源和循环缓冲区，并将就绪样本关联到运行、群和串。电流服务从板级样本视图读取有效样本。`dac.h` 提供输出电压档设定；`comp.h` 提供比较器过流检出与锁存输入（FLT4/FLT5）。
- **普通时基和看门狗。** `timebase.h` 定义单调时间戳的读取、单位和回绕约定（32/64 位定宽、回绕安全比较助手），用于普通截止时间（50 ms 半包计时、串级截止）；FreeRTOS tick 由 SysTick 提供，仅用于任务延时，业务层统一经 `timebase.h` 取时、双时基不混用。`iwdg.h` 封装 IWDG 硬件（LSI 标称 32 kHz、预分频 ÷8、重载 3999 及刷新）；`watchdog.h` 提供任务监视器的刷新服务接口，由 BSP 配置并启动硬件看门狗，由任务监视器（svc/watchdog_monitor）按 E-008 决定何时刷新。`led.h` 提供 1 Hz 翻转的板载 LED 指示。
- **精确定时输出和板级保护。** `sequence_io.h` 向运行控制提供装载、放行、封锁和读取事件等操作。BSP 用 STM32 HRTIM 驱动实现定时与输出控制，并用 HAL/LL 配置 GPIO、EXTI、DAC 和比较器。杆状态、端口事件和过流锁存是板级接口上的能力。比较器保护采用 HRTIM 硬件故障态，端口 MCU 快路径采用 EEV7 输出复位。独立锁存关断连线和端口持续封锁见 §5。
- **config/data/ops 绑定模型。** `drv/` 九个驱动（uart、adc_capture、dac、comp、iwdg、flash、led、timebase、watchdog）统一采用静态实例模型：config 结构、data 结构、ops 函数表，构建期绑定到 psg_board_config.h 声明的板级实例；主机测试链接同一公开接口的替身实现，零编译开关切换。驱动拥有寄存器操作、搬运进度、完成和错误状态，板级配置拥有具体的资源绑定。参考 Zephyr 设备模型、TinyUSB BSP 与 grblHAL 板卡映射（见[嵌入式固件分层调研](embedded-layering-research.md)）。
- **测试注入。** `timebase.h` 提供 set_time/advance 注入接口，主机脚本时钟推进任务；psg_sequence_io 测试替身覆盖 TIMA 串结束、DMA 就绪与保护事件全谱；失约注入钩子为编译期测试宏、发布版零残留（N-005），用于人为延迟结算任务或丢弃就绪事件、验证 F-041 终止路径。

## 源码依赖与状态归属

- `app/` 使用 `run/` 与 `svc/` 公开入口（pulse_engine、settlement、identity、dedup、fault、watchdog_monitor）。启动入口绑定目标板实例。`run/` 使用波形计划、结算接口和 `sequence_io.h`。计划参数与装载描述通过值数据交接，板级依赖自己的执行接口。
- psg_ecsp 依赖 `uart.h`，标识服务依赖 `flash.h`。任务监视器（svc/watchdog_monitor）经 `timebase.h`、`watchdog.h` 设备接口取时与喂狗，主机测试可注入替身。`bsp/psg_v3/` 通过 `adc_capture.h`、`dac.h`、`comp.h` 获取采集与外设能力，并通过 STM32G4 驱动绑定具体外设。板级和驱动用各自的事件与完成接口经队列向任务交付观测结果。
- 模块私有头文件只在各自目录内使用。主机测试可替换设备实现，沿实际公开入口驱动命令和运行状态。

[验收用例](../verification/firmware.md)

1. **0x34 写入、0x35 读回。** 协议任务映射线上字段，运行控制校验候选配置，计划服务生成对应的执行参数。候选配置和计划同时提交。读回由运行控制提供原值，后续启动装载与已提交配置对应的计划。
2. **上一串结算与下一串放行。** TIMA 串结束事件由 ISR 直接入结算任务队列，结算任务事件驱动收齐同串事件与各参与通道的 DMA 就绪及样本有效范围，判定完成经任务通知唤醒脉冲引擎任务决定放行。BSP 只执行与该串标识和原定开始时刻匹配的许可，到时缺许可则保持输出封锁。脉冲引擎任务按 F-041 终止本次运行。分别测量取样、结算和放行用时。
3. **端口停止与过流并发。** 硬件执行比较器或锁存触发的停波，ISR 捕捉过流来源和样本边界。端口停止触发 EEV7 硬件输出复位，事件经 TIMA CPT1 捕获入队。脉冲引擎任务根据事件的运行归属更新异常记录和状态快照，必要时由协议任务提交 0x3C。空闲过流锁存上报按 E-002，故障字 bit0 的自检及清除判定按 E-003、I-021。
4. **版本写入期间保持通信与出波时序。** 标识服务任务分步推进 Flash，脉冲引擎与结算任务按期处理出波与结算，协议任务继续按预算推进；擦写窗口内记录读取走 RAM 缓存。烧写时序和实际串级余量通过实板验证。

主机自动化测试通过公开接口注入板级事件和带接收时刻的串口数据：板级事件经 psg_sequence_io 测试替身注入（覆盖 TIMA 串结束、DMA 就绪与保护事件全谱），失约注入钩子（编译期测试宏，发布版零残留）人为延迟结算任务或丢弃就绪事件以验证 F-041 终止路径，脚本时钟经 timebase 的 set_time/advance 注入接口推进。PC 串口联调在两种构建上运行同一套 ECSP 用例。实板台架验收串级截止时间、保护停波延迟、DMA 归属与 Flash 擦写负载等物理行为。三类入口的详细覆盖范围见固件实现规格。
