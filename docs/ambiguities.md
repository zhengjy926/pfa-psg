# 文档疑点与待补项

本文件记录影响实现、验收或联调的资料冲突与缺口。条目给出当前来源、影响和需要确认的问题。确认后的行为写回对应规范。

## PSG 行为与验收

| 事项 | 现有依据 | 需要确认 |
| --- | --- | --- |
| 空闲时硬件过流锁存 | [SRS §5](srs/pulse-gen-firmware.md#5-异常与安全需求e-) 的 E-002 写「没有运行时过流不记录、不锁存」。E-003 及 [板卡协议 §4](spec/board-pulse-gen.md#4-故障字位分配) 又记录空闲硬件锁存置 bit1 并触发 0x11。 | E-002 是否仅指不进入电流异常态、不记运行中的通道异常，硬件锁存和故障字仍按 E-003？还需确定锁存已有效而固件尚未开始检测时按电平还是按正向过渡置位。 |
| 空闲改杆与首串前切换 | [SRS §2.3](srs/pulse-gen-firmware.md#23-杆与杆选通) 的 F-032 将杆切换限定在脉冲串间隔，F-033 要求空闲设置成功后立即生效。0x40 旧条款曾要求停用杆对循环时受理启动后六杆全通，边沿触发时等待 R 波、触发延迟、群间隔、结算和触发间歇也持续全通。[0x42 卡片](spec/board-pulse-gen.md#0x42-设置杆选通设置类) 明确各脉冲串按杆选通。 | 明确 F-032 的适用阶段、串外杆状态及首串前的导通等待。PRM-511 与 F-031 的 PRM-508 是否描述同一等待？ |
| 电流异常的上报值与通道归属 | [SRS F-043](srs/pulse-gen-firmware.md#24-电流采样齐样与结算) 与 [0x31 卡片](spec/board-pulse-gen.md#0x31-获取脉冲输出状态获取类) 用「电流异常结束」作为条件，却以过流瞬间采样计算。欠流在群结算时才判定。 | 欠流结束时两路电流分别取什么值？单通道过流时未异常通道的状态码及电流采用哪套规则？两路同时报错时如何呈现？ |
| 结算时间边界 | [SRS F-040](srs/pulse-gen-firmware.md#24-电流采样齐样与结算) 同时要求结算时间 ≤ PRM-119，且结算等待与结算时间之和严格小于 PRM-118。登记的默认等待与独立上限恰好等于总上限。 | 默认等待走满并恰好达到结算时间上限时验收不通过。需要确认这是否是有意的联合约束，还是应修改其中一个边界。 |
| 掉线时正在运行的输出 | [ECSP §5.3](spec/ecsp-general.md#53-异常场景处理) 要求掉线后双方进入安全状态或降级模式。SRS 历史裁决 TBR-04 记录「运行中断链不处置」，现行 SRS 无对应条款。 | 确认 TBR-04 仍适用后恢复 PSG 的行为条款，并说明与 ECSP 通用规则的关系。 |

## ECSP 与联调契约

| 事项 | 现有依据 | 需要确认 |
| --- | --- | --- |
| 扩展码的字段与边界 | [ECSP §3](spec/ecsp-general.md#3-命令集合) 同时把 0x22–0x2F 描述为保留命令码的子段和板卡扩展段。§5.1 则称它为扩展应答码段。PRM-026 的上界 0x22 与 PRM-033 的起点重合。 | 确认命令码 0x22–0x2F 是否全部保留，应答码 0x22 的归属，以及 PRM-026 是通用应答码范围还是其它口径。 |
| 长耗时命令的中止控制码 | [ECSP §4.4](spec/ecsp-general.md#44-长耗时命令处理机制) 写控制码 0x01 主动终止，§5.1 的 0x21 同样引用 0x01。0x08 与 0x0C 的命令卡片都把 0x01 定义为启动、0x00 定义为停止。 | 确认通用流程是引用各命令的停止码，还是给所有长耗时动作规定统一值。 |
| 最大载荷的计算口径 | PRM-010 为 9 字节开销、PRM-011 为 512 字节整帧、PRM-013 为最大载荷 502 字节。[ECSP §2](spec/ecsp-general.md#2-帧与编码) 把应答码算在应答载荷内。 | 502 是否仅指应答码之后的数据？分别给出请求、事件和应答的边界及相应长度检查。 |
| 故障保留位 | [ECSP 0x11 卡片](spec/ecsp-general.md#0x11-故障主动上报事件类单次) 将 bit1–bit7 同时称为保留位与板卡可分配位，并要求保留位置位按未知故障处理。PSG 在 [板卡协议 §4](spec/board-pulse-gen.md#4-故障字位分配) 分配 bit1。 | 确认「未知故障」判断是否仅适用于该节点未分配的位，并确认产品内不同节点复用位号的约束。 |
| 重新握手的参数重配 | [ECSP §4.2](spec/ecsp-general.md#42-上电与握手流程) 要求从机停业务、主机重配。SRS 历史裁决 TBR-04 提到重新握手触发中途停止和清参数；现行 E-009 只明确系统复位后参数恢复默认。 | 确认 PSG 收到就绪态的重复握手时从机要清除的参数，以及该动作和故障字、电流异常态的关系。 |
| 交付版本标识 | [SRS I-010](srs/pulse-gen-firmware.md#32-命令与载荷) 点名协议 V0.2；[ECSP §7.2](spec/ecsp-general.md#72-版本核对与实例声明) 的 V1.0 位于示例模板，产品配置的期望软件版本仍缺。 | 提供 PSG 所用的正式协议版本和对应固件完整版本，再填写产品配置（A-12）。 |

## 已裁决

| 事项 | 写回位置 |
| --- | --- |
| 空闲时，杆对循环停用按杆选通，启用仅 AB 导通。故障字 bit1 置位或电流异常时六杆全断。 | SRS F-028、板卡协议 0x40/0x42 |
| 空闲时，合法的 0x30 停止请求回 0x00，保持空闲和杆选通。 | SRS F-012、板卡协议 0x30 和表 3-2 |
| 合法 0x30 请求同时遇到电流异常锁定与启停源不匹配时，按现有板卡矩阵返回 0x15。ECSP 主机收到此码后停止自动重试。 | SRS F-004、板卡协议表 3-2 |
| 空闲且故障字 bit1 为 0 时，0x3D 直接回成功。 | SRS I-021、板卡协议 0x3D 和表 3-2 |
| 0x3D 清除 bit1 后，物理杆状态立即恢复到 F-028 的空闲配置。 | SRS I-021、E-003；板卡协议 0x3D 和表 3-2 |
