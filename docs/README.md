# 文档索引与阅读约定

本仓库的文档面向两类读者：**实现固件的 Agent** 与**人**。两者读同一套文件；Agent 优先，人可读性靠结构保证。

## 1. 先读什么

| 1 | [`../GLOSSARY.md`](../GLOSSARY.md) | 领域词汇的唯一定义处。任何术语以它为准，含 `_Avoid_` 禁用同义词 | 现行 |
| 2 | [`srs/pulse-gen-firmware.md`](srs/pulse-gen-firmware.md) | 需求规格，验收权威。需求 ID：`F-`（功能）、`I-`（接口）、`T-`（时序）、`E-`（异常）、`N-`（非功能） | 现行 |

| 4 | [`spec/board-pulse-gen.md`](spec/board-pulse-gen.md) | 本板实例化：板卡功能命令 0x30–0x45、故障位分配、符合性矩阵 | 现行 |

## 2. 权威链

同一事实在多处出现时，按下列顺序判胜；下级不得改写上级语义：

1. **需求规格**（`srs/`）——「做什么」与验收判据的权威。
2. **ECSP 通用规范**（`spec/ecsp-general.md`）——线上协议语义与应答码的权威；实例化文档不得修改通用命令或应答码语义（依据原文 §1.2）。
3. **板卡/产品规范**（`spec/`）——实例化，只允许**收窄**（声明支持级别、分配位、给出本板取值），不允许放宽或改写。
4. **MCU 配置**（`hw/`）——实现绑定，描述如何落到芯片；不得反过来约束协议或需求。

数值一律以 [`params.md`](params.md) 为准。任何文档正文不重复写数值，只引用 `PRM-xxx`。

## 3. 编号与标记约定

| 记号 | 含义 | 出现位置 |
| --- | --- | --- |
| `PRM-001` | 参数登记项，定义在 `params.md` | 任何文档 |
| `Q-001` | 未裁决问题，定义在 `OPEN_QUESTIONS.md` | 任何文档 |
| `F-` / `I-` / `T-` / `E-` / `N-` | 需求 ID，定义在 SRS | 任何文档 |
| `[待确认 Q-001]` | 该处受未裁决问题影响，暂按「建议值」实现，裁决后回填 | 规范正文 |
| `[未收录]` | 原文确实没有该内容，不得臆造 | 规范正文 |
| `[本版不实现]` | 需求存在但本版不交付 | SRS |

**「应 / 不得 / 当…时」** 表示强制条款；**「可 / 建议」** 表示非强制。原文中的「必须」一律降为「应」，避免与需求的强制级别混淆。

## 4. 文档骨架

### 4.1 协议类（`spec/*.md`）

```
# <文档名>（<角色>）
> 权威链、状态见 README
## 1 范围与角色
## 2 帧与编码            ← 只写本层特有内容，通用层内容给引用
## 3 命令集合
  3.1 总表（命令码/名称/类别/方向/变长/幂等/落点）
  3.2 命令卡片（每条一节，模板见 4.2）
## 4 机制（握手/幂等/长耗时/复位/低功耗）← 仅通用层
## 5 异常与应答码
## 6 时序
## 7 版本与兼容
## 8 符合性矩阵
## 附录 A 变更记录  B 待评审  C 实例化清单
```

### 4.2 命令卡片模板（固定字段，顺序不变；不适用写 `—`）

```
### 0x30 启动/停止脉冲输出（动作类）

| 项 | 值 |
| --- | --- |
| 命令码 | 0x30 |
| 方向 | Host→Slave |
| 类别 | 动作类 |
| 载荷长度 | 2 B 定长 |
| 幂等 | 否（带事务序号） |
| 应答时限 | PRM-103 |
| 前置条件 | F-004 |
| 拒绝码 | 0x11 / 0x13 / 0x15 |

**请求载荷**

| 偏移 | 字段 | 类型 | 字节 | 约束 | 来源 |

**应答载荷**

| 偏移 | 字段 | 类型 | 字节 | 约束 | 来源 |

**约束**

- 应……（一条一句，可被单独引用；编号 `C-0x30-01` 递增）

**示例**

```
FA | 0A 00 | 03 | 30 | 02 | 00 01 | 4B 37 | 0D
```
```

示例帧书写规则：字节用两位大写十六进制；`|` 分隔字段组；CRC 位置写**实算值**，并在该卡片末尾注明「示例由 `tools/frame_check.py` 复核」。所有示例必须满足 `LEN = 9 + 载荷长度`。

### 4.3 需求类（`srs/*.md`）

保持现有 `F-`/`I-`/`T-`/`E-`/`N-` 编号与表格形态，只做三件事：补齐追溯列（`PRM-xxx`、命令卡片）、把不可验证条目改写成可判定语句并链 `Q-xxx`、删除与协议文档重复的叙述（改为引用）。

### 4.4 硬件类（`hw/*.md`）

一张表一条事实：引脚表必须有 `信号 / 引脚 / 方向 / 复用功能(AF) / 上电默认 / 归属需求` 六列；外设表必须是「一条参数一行」，禁止「参数成行、外设成列」的转置表（加外设会改表宽）。

## 5. 维护规则

1. 改数值 → 先改 `params.md`，再改引用处；不允许只在正文改数。
2. 新增命令 → 总表 + 卡片 + 符合性矩阵 + 需求 ID，四处齐全才算完成。
3. 发现冲突 → 记 `OPEN_QUESTIONS.md`，正文标 `[待确认 Q-xxx]`，不要就地择一。
4. 原文缺失 → 标 `[未收录]`，不要补写。
