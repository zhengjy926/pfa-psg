# 采用 FreeRTOS 全量任务化调度

PSG v3 采用 FreeRTOS 全量任务化调度，取代原裸机协作式前台调度。背景：协作式调度的每轮有界预算逼近上限——群级等待与结算的默认合计 50 ms 预算被评估为须收紧（[串级结算验证](../design/current-settlement.md#截止时间与验证)），且每轮预算与静态缓冲容量互为循环依赖，最坏负载下只能靠任务抢占解决的时限冲突已经出现。决策：任务监视器（最高优先级）、脉冲引擎、电流结算、协议任务、UART 接收、标识服务（最低优先级）六个任务，按任务级周期、最坏执行时间（WCET）和优先级分配预算；原调度与 ECSP 分派合并为协议任务，作为请求裁定链单一所有者（ECSP 解帧去重与调度编排，脉冲引擎只执行已裁定操作）；ISR 与任务之间经队列或通知交接；保护停波仍由板级硬件与中断快速路径直接执行，不经过任务。后果：废止协作式每轮处理预算，结算任务对应 PRM-117～PRM-119、协议任务对应 PRM-101～PRM-106 的任务级预算；喂狗改为任务监视器模式（E-008），按 100 ms 周期采样各任务的原子推进标记、连续 2 次逾期即拒喂，监视器零共享资源、最坏喂狗间隔小于 PRM-603 的最短硬件窗口 0.941 s；任务栈与队列 RAM 计入 PRM-602 资源上限（N-002），静态 RAM 总预算 ≤32 KB（PRM-602 的一半余量，FreeRTOS 内核、六任务栈、各队列、DMA 2 KiB、双槽快照、去重 FIFO 与 ECSP 缓冲逐项计入），启用 configCHECK_FOR_STACK_OVERFLOW=2 栈金丝雀并以 map 文件核对。医疗安全认证影响评估不在本项目范围。 [SRS F-040、F-041、T-011、E-008、N-002](../srs/pulse-gen-firmware.md) · [固件架构](../design/firmware-architecture.md) · [串级结算验证](../design/current-settlement.md#截止时间与验证)
